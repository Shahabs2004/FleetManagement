# معماری فنی سامانه مدیریت ناوگان

## سبک معماری

سامانه با رویکرد Clean Architecture و الگوی Modular Monolith ساخته می‌شود. برنامه در نسخه نخست یک واحد قابل استقرار روی IIS است، اما مرزهای ماژول‌ها و لایه‌ها در کد رعایت می‌شوند.

## لایه‌ها

### Domain
- موجودیت‌ها، Value Objectها و قوانین اصلی کسب‌وکار
- بدون وابستگی به Blazor، EF Core یا زیرساخت
- هر قاعده مهم کسب‌وکار باید در این لایه یا در سرویس دامنه مناسب بیان شود.

### Application
- سناریوهای کاربردی و گردش‌کارها
- اعتبارسنجی ورودی‌ها و مجوزهای عملیاتی
- قراردادهای موردنیاز برای مخازن و سرویس‌های بیرونی
- هماهنگ‌سازی عملیات ماژول‌ها

### Infrastructure
- پیاده‌سازی دسترسی به SQL Server با EF Core 10
- اتصال Active Directory و سرویس پیامک ADP
- پیاده‌سازی ذخیره‌سازی، گزارش‌گیری و سرویس‌های فنی
- Migrationهای پایگاه داده

### Presentation
- برنامه Blazor Web App با Interactive Server
- صفحات فارسی و راست‌چین
- اجزای رابط کاربری و مدیریت تعامل کاربر
- نمایش خطاهای کاربرپسند بدون افشای جزئیات فنی

## ماژول‌های دامنه‌ای

1. راه‌اندازی اولیه و تنظیمات
2. کاربران، احراز هویت و مجوزها
3. ساختار سازمانی و گروه‌ها
4. رانندگان
5. خودروها
6. مکان‌ها
7. درخواست‌ها و مأموریت‌ها
8. زمان‌بندی و تایم‌لاین
9. کیلومتر و کارکرد
10. داشبورد و گزارش‌ها
11. اعلان‌های داخلی
12. پیامک
13. ممیزی و تاریخچه نشست‌ها
14. چاپ دستور مأموریت

هر ماژول باید سرویس‌ها، اعتبارسنجی‌ها و قواعد کسب‌وکار خودش را داشته باشد. ارتباط بین ماژول‌ها از قراردادهای روشن و Application Serviceها عبور می‌کند.

## قواعد وابستگی

- Domain به هیچ پروژه دیگری وابسته نیست.
- Application به Domain وابسته است.
- Infrastructure قراردادهای Application را پیاده‌سازی می‌کند.
- Presentation از Application استفاده می‌کند و جزئیات Infrastructure را مستقیماً فراخوانی نمی‌کند.
- از ایجاد وابستگی حلقوی بین ماژول‌ها جلوگیری می‌شود.

## فناوری‌های منتخب

- .NET 10 LTS / C# 14
- Blazor Web App / Interactive Server
- Entity Framework Core 10
- SQL Server
- IIS و Windows Server
- SignalR برای ارتباط بلادرنگ؛ در Interactive Server از زیرساخت ارتباطی موجود تا حد امکان استفاده می‌شود.

## زمان و زبان

- منطقه زمانی کاربردی: Asia/Tehran
- تقویم و نمایش تاریخ: شمسی
- زبان رابط کاربری: فارسی
- جهت رابط: RTL
- دقت زمان‌های عملیاتی: ساعت کامل، بدون دقیقه
- ذخیره‌سازی زمان در پایگاه داده باید به‌صورت سازگار و قابل تبدیل انجام شود؛ نمایش شمسی در لایه ارائه انجام می‌شود.

## نکته‌های تصمیم‌گیری باز

- نسخه دقیق Windows Server و IIS مقصد باید پیش از انتشار نهایی با .NET 10 تطبیق داده شود.
- جزئیات روش احراز هویت Windows Integrated در IIS و روش ورود جایگزین AD باید در مرحله پیاده‌سازی امنیتی طراحی و آزمایش شود.
- سیاست نگهداری و پشتیبان‌گیری کلیدهای لازم برای بازیابی حساب اضطراری باید مستند شود.
