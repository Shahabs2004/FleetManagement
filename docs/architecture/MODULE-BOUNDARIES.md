# مرزهای ماژول‌های سامانه

این سند مرز مسئولیت ماژول‌ها را مشخص می‌کند تا با رشد پروژه، منطق کسب‌وکار در یک بخش انباشته نشود.

| ماژول | مسئولیت اصلی |
|---|---|
| Setup | راه‌اندازی اولیه، آزمون آمادگی و بازیابی محدود |
| IdentityAccess | ورود محلی اضطراری، AD، کاربران، نقش‌ها و مجوزها |
| Organization | واحدهای سازمانی و نگاشت گروه‌های AD |
| Drivers | اطلاعات و وضعیت رانندگان |
| Vehicles | اطلاعات، وضعیت و آرشیو خودروها |
| Locations | فهرست مکان‌ها و پیشنهاد مکان جدید |
| Missions | درخواست، تأیید، اجرا، لغو، انصراف و تقسیم مأموریت |
| Scheduling | تایم‌لاین، رزرو منابع و کنترل تداخل |
| Mileage | کیلومترشمار، پیوستگی کیلومتر و محاسبه کارکرد |
| Notifications | اعلان‌های داخل سامانه |
| Sms | صف پیامک، الگوها، تلاش مجدد و گزارش ارسال |
| Reporting | گزارش‌ها، داشبورد و خروجی‌ها |
| Auditing | ممیزی عملیات و تاریخچه نشست‌ها |
| MissionOrders | قالب و چاپ دستور مأموریت |

## قواعد تعامل

- ماژول Missions مالک چرخه عمر مأموریت است.
- Scheduling مسئول محاسبه تداخل و قواعد تخصیص بازه زمانی است و نباید مالک وضعیت مأموریت شود.
- Mileage مالک قواعد پیوستگی کیلومتر و محاسبه مسافت است.
- Sms فقط رویدادهای دامنه‌ای را دریافت می‌کند و نباید منطق مأموریت را تغییر دهد.
- Auditing باید از مسیرهای کاربردی مهم رویداد دریافت کند؛ حذف یا ویرایش سوابق ممیزی از رابط کاربری مجاز نیست.
- گزارش‌ها داده ماژول‌ها را فقط‌خواندنی مصرف می‌کنند و مالک داده عملیاتی نیستند.
- ارتباط بین ماژول‌ها از قراردادهای Application یا رویدادهای داخلی کنترل‌شده عبور می‌کند.

## پیاده‌سازی تدریجی

در ابتدا فقط زیرساخت مشترک و میزبان وب ساخته می‌شود. هر ماژول هنگام ورود به فاز پیاده‌سازی، با کلاس‌های کوچک و تست‌های مستقل توسعه می‌یابد.
