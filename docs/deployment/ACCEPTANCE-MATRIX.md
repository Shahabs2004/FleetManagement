# ماتریس پذیرش و وضعیت عملیاتی FleetManagement

**مبنای تطبیق:** `docs/SPEC.md` بخش‌های ۱۷ و ۲۰، کد و آزمون‌های شاخه `develop`.
**آخرین شواهد CI روی HEAD شاخه develop:** Run شماره ۸۰۰ روی commit `0da1f88`؛ هر دو job ساخت Windows و آزمون یکپارچه SQL Server 2022 موفق بوده‌اند.

> «پیاده‌سازی‌شده» به معنی وجود کد و آزمون است، نه تأیید عملکرد در محیط واقعی. موارد IIS، Windows Authentication، LDAPS، پیامک واقعی، بار، امنیت و Backup/Restore تا ثبت نتیجه در محیط سازمان «تأییدنشده» باقی می‌مانند.

## قواعد ثبت نتیجه

1. برای هر ردیف، تاریخ، نسخه برنامه، نام محیط، مسئول اجرا و پیوند شواهد را در زمان پذیرش سازمان ثبت کنید.
2. وضعیت «موفق در CI» فقط آزمون خودکار مخزن را توصیف می‌کند؛ جایگزین پذیرش IIS، AD، LDAPS، پیامک، Backup/Restore یا آزمون بار نیست.
3. رمز، Connection String، کد bootstrap، شماره/نام واقعی افراد، پاسخ خام حاوی داده شخصی و Backup در Git یا گزارش عمومی قرار نگیرد.
4. نتیجه ناموفق باید همراه شناسه پیگیری و اقدام اصلاحی ثبت شود؛ تا رفع و تکرار آزمون، وضعیت «تأییدنشده» باقی بماند.


## راهنمای عملیاتی تکمیلی

جزئیات پیش‌نیازها، گام‌های نصب و تنظیم، راستی‌آزمایی، نتیجه مورد انتظار، مسئول و رفتار هنگام شکست برای IIS، Application Pool، .NET 10 Hosting Bundle، Blazor Interactive Server/SignalR، Windows Authentication، LDAPS، SQL Server و ACL در [راهنمای استقرار IIS و Active Directory](iis-active-directory.md) آمده است. اجرای همه این موارد در محیط واقعی سازمان همچنان **تأییدنشده** است و باید با شواهد توسط مسئول مربوط ثبت شود.
