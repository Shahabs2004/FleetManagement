# چک‌لیست انتشار و استقرار سامانه

این راهنما برای انتشار نسخه آزمایشی/عملیاتی در شبکه داخلی است. مقادیر نام سرور، نام پایگاه داده، دامنه و Application Pool باید در زمان استقرار با اطلاعات واقعی سازمان جایگزین شوند.

## پیش‌نیازهای سرور

- Windows Server نسخه پشتیبانی‌شده سازمان با آخرین به‌روزرسانی‌های امنیتی.
- IIS و قابلیت ASP.NET Core Hosting.
- .NET 10 Hosting Bundle متناسب با معماری سرور.
- SQL Server موجود سازمان؛ نصب SQL Server جدید در دامنه این پروژه نیست.
- گواهی HTTPS معتبر برای نام DNS داخلی سامانه.
- دسترسی شبکه از سرور برنامه به SQL Server و Domain Controller.
- برای LDAPS، اعتماد به زنجیره گواهی CA سازمان روی سرور برنامه.

## انتشار برنامه

1. از شاخه پایدار main یک نسخه مشخص و بازبینی‌شده انتخاب کنید.
2. روی عامل انتشار، دستورهای restore و test را اجرا کنید.
3. خروجی Web را با دستور زیر تولید کنید:

```powershell
dotnet publish src/FleetManagement.Web/FleetManagement.Web.csproj -c Release -o <publish-folder>
```

4. پوشه انتشار را در مسیر ثابت و محدودشده روی سرور کپی کنید.
5. پیش از اولین اجرای برنامه، اسکریپت `scripts/windows/Prepare-Server.ps1` را با دسترسی Administrator و نام واقعی Application Pool اجرا کنید تا پوشه محرمانه bootstrap و ACL محدود آن ایجاد شود؛ برنامه را پیش از این مرحله اجرا نکنید.
6. در IIS یک Application Pool مستقل ایجاد کنید؛ مقدار .NET CLR Version روی No Managed Code و حالت ۶۴ بیتی فعال باشد.
7. هویت Application Pool را به یک هویت اختصاصی با حداقل مجوز لازم تنظیم کنید.
8. وب‌سایت را به پوشه انتشار متصل و HTTPS را فعال کنید.
9. در Authentication، Anonymous Authentication برای صفحه ورود فعال بماند و Windows Authentication نیز فعال شود. Providerهای Negotiate و NTLM مطابق سیاست دامنه سازمان تنظیم شوند.
10. مطمئن شوید فایل web.config خروجی publish بدون تغییر در ریشه برنامه قرار دارد.

## پایگاه داده

1. از SQL Server موجود، یک پایگاه داده اختصاصی برای سامانه انتخاب کنید.
2. یک SQL Login اختصاصی بسازید و دسترسی‌های لازم برای ایجاد/اعمال Migrationها و اجرای برنامه را به آن بدهید.
3. دسترسی شبکه SQL Server را فقط به سرور برنامه و مدیران مجاز محدود کنید.
4. در ویزارد راه‌اندازی، نام سرور، پایگاه داده، SQL Login و رمز آن را وارد کنید.
5. اتصال را آزمایش کنید و اجرای Migrationها و بررسی نهایی ساختار را تا پایان دنبال کنید.
6. پیش از هر ارتقای نسخه، نسخه پشتیبان معتبر پایگاه داده را بررسی کنید.
7. زمان‌بندی Backup و آزمون Restore بر عهده زیرساخت SQL سازمان است؛ برنامه ماژول Backup مستقل ندارد.

## راه‌اندازی اولیه

- کد اولیه مدیر محلی را از مسیر سرور دریافت کنید.
- حساب مدیر محلی اضطراری را با رمز قوی ایجاد و ورود مستقل آن را آزمایش کنید.
- تنظیمات AD را با LDAPS و گروه‌های مجاز واقعی سازمان ثبت و اتصال را تأیید کنید.
- نام و نشان سازمان را وارد کنید.
- مرحله پیامک فقط در اختیار مدیر فنی است. رمزها را در هیچ گزارش یا مخزن کد قرار ندهید.
- پیش از تکمیل ویزارد، دسترسی فایل کد مدیر فنی را طبق راهنمای iis-active-directory.md محدود کنید.
- پس از تکمیل ویزارد، حذف خودکار فایل کد مدیر فنی را از روی سرور بررسی کنید.

## آزمون پذیرش پیش از بهره‌برداری

- ورود AD با حساب فعال، غیرفعال، قفل‌شده و خارج از گروه مجاز.
- ورود مدیر سامانه به صفحه تنظیمات Active Directory، تغییر مشخصات اتصال و گروه‌ها، حفظ رمز قبلی در صورت خالی‌بودن فیلد رمز، آزمون LDAPS و ثبت عامل تغییر بدون درج رمز در ممیزی.
- ورود یکپارچه ویندوز از Edge و Chrome و Firefox سازمانی.
- ورود مدیر محلی در زمان قطع AD و بازیابی در زمان قطع SQL.
- آزمون محدودسازی نرخ ورود: بیش از ۱۰ درخواست در دقیقه از یک IP باید با HTTP 429 پاسخ داده شود؛ رفتار پشت Reverse Proxy نیز بررسی شود.
- اعمال نقش، مجوز Grant و Deny و غیرفعال‌سازی داخلی کاربر.
- آزمون تفکیک مشاهده و مدیریت راننده و خودرو: نقش صرفاً مشاهده‌گر نباید بتواند ثبت، ویرایش، بایگانی یا تغییر خودروی پیش‌فرض را انجام دهد.
- آزمون مجوزهای عملیاتی مأموریت: مشاهده صف بررسی به‌تنهایی نباید مجوز تأیید، رد، لغو، تمدید یا تقسیم مأموریت ایجاد کند.
- آزمون دسترسی داشبورد، چاپ دستور و خروجی Excel بر اساس مجوزهای مستقل مربوطه.
- ثبت و تأیید/رد درخواست مأموریت و کنترل تعارض راننده و خودرو.
- کنترل شروع/پایان خودکار، لغو، انصراف، تمدید، کیلومترشمار و تقسیم مأموریت.
- جلوگیری از بایگانی راننده یا خودرو و غیرفعال‌کردن راننده دارای مأموریت فعال؛ تغییر وضعیت خودرو به تعمیرگاه یا خارج از سرویس هنگام مأموریت فعال نیز باید مسدود شود.
- بررسی گزارش ممیزی، سوابق نشست و تنظیم مهلت بیکاری.
- ورود با نقش مدیر سامانه به صفحه مشخصات سازمان، تغییر نام و نشان، حذف نشان و ثبت عامل واقعی تغییر در گزارش ممیزی.
- چاپ دستور مأموریت روی کاغذ A4 و بررسی لوگو، امضاها و تقویم جلالی.
- بررسی گزارش‌ها و فایل Excel خروجی.
- آزمون قطعی SQL، بازگشت اتصال و رفتار صفحه بازیابی.
- آزمون هم‌زمانی با تعداد کاربر مورد انتظار سازمان.

## مواردی که قبل از تأیید عملیاتی باید تکمیل شوند

- آزمون واقعی IIS/Windows Authentication و LDAPS در دامنه سازمان.
- تأیید نسخه دقیق Windows Server و SQL Server.
- کد ارسال پیامک و استعلام وضعیت طبق WSDL ارائه‌دهنده در مخزن پیاده‌سازی شده است؛ آزمون واقعی ارسال و تأیید نگاشت وضعیت‌ها روی سرور سازمان انجام شود.
- آزمون بار، امنیت، بازیابی و پذیرش کاربران نهایی.
- تعیین مسئولیت نگهداری، Backup/Restore و پایش سرور در سازمان.

## اطلاعات محرمانه

هیچ رمز SQL، رمز AD، رمز پیامک، کد مدیر فنی، فایل bootstrap عملیاتی، داده کاربران یا Backup نباید در Git ثبت شود. تنظیمات حساس عملیاتی مطابق تصمیم پروژه در SQL نگهداری می‌شوند؛ اطلاعات حداقلی لازم برای راه‌اندازی و بازیابی در فایل محلی محافظت‌شده باقی می‌مانند.


- مشاهده صفحه سوابق کیلومترشمار با فیلتر خودرو، نمایش راننده و مأموریت مرتبط، تفکیک مقادیر ثبت‌نشده و تطبیق مسافت با اختلاف کیلومترشمار شروع و پایان.
