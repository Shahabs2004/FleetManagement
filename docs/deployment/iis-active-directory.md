# راهنمای استقرار ورود Active Directory در IIS

## پیش‌نیازها

- Windows Server و IIS با نقش **Windows Authentication** نصب‌شده.
- .NET 10 Hosting Bundle متناسب با نسخه برنامه.
- گواهی معتبر HTTPS برای وب‌سایت داخلی.
- دسترسی شبکه سرور برنامه به Domain Controller روی پورت LDAPS (معمولاً 636).
- حساب سرویس AD با حداقل مجوز خواندن کاربران و گروه‌های موردنیاز.
- گواهی CA سازمان روی Windows Server مورد اعتماد باشد تا اعتبارسنجی TLS در LDAPS موفق شود.

## تنظیمات احراز هویت IIS

1. برنامه را روی یک وب‌سایت یا Application مستقل در IIS منتشر کنید.
2. در بخش **Authentication**، گزینه Anonymous Authentication را فعال نگه دارید تا صفحه ورود نمایش داده شود.
3. Windows Authentication را فعال کنید.
4. Providerهای Negotiate و سپس NTLM را فعال نگه دارید؛ در صورت پشتیبانی کامل محیط، Negotiate اولویت دارد.
5. فایل web.config همراه خروجی انتشار باید در ریشه برنامه قرار داشته باشد.
6. دسترسی HTTPS را الزامی کنید. کوکی نشست برنامه فقط روی HTTPS ارسال می‌شود.
7. در مرورگرهای سازمانی، نشانی سامانه را در Intranet Zone یا فهرست مجاز احراز هویت یکپارچه قرار دهید.

## جریان ورود

- ورود جایگزین، نام کاربری و رمز عبور را از فرم دریافت می‌کند و با LDAPS به AD متصل می‌شود.
- ورود یکپارچه، هویت احراز‌شده توسط IIS را دریافت و وضعیت حساب و گروه‌های مجاز را دوباره در AD بررسی می‌کند.
- هر دو روش پیش از صدور کوکی برنامه، وضعیت فعال حساب و عضویت مستقیم یا تو‌در‌توی گروه‌های مجاز را کنترل می‌کنند.
- پروفایل کاربر در اولین ورود در جدول ApplicationUsers ساخته می‌شود و در ورودهای بعدی با AD همگام می‌شود.
- غیرفعال‌سازی داخلی سامانه بر فعال بودن حساب AD اولویت دارد و با فعال‌شدن مجدد حساب در AD خودکار برطرف نمی‌شود.

## عیب‌یابی

- اگر گزینه Windows Authentication در IIS وجود ندارد، نقش/Feature مربوطه را نصب کنید.
- اگر Windows Authentication فعال است ولی ورود یکپارچه انجام نمی‌شود، تنظیمات Intranet Zone مرورگر و Providerهای IIS را بررسی کنید.
- اگر LDAPS خطا می‌دهد، زنجیره گواهی سرور LDAP و تطبیق نام DNS گواهی با نام سرور را بررسی کنید.
- از غیرفعال‌کردن اعتبارسنجی گواهی TLS در محیط عملیاتی خودداری کنید.
- خطاهای فنی در گزارش سرور ثبت می‌شوند؛ رمز عبور کاربر نباید در گزارش‌ها ثبت شود.

## محافظت از فایل‌های bootstrap و کد مدیر فنی

فایل‌های اولیه در مسیر زیر نگهداری می‌شوند:

`C:\ProgramData\FleetManagement`

فایل وضعیت bootstrap با DPAPI و محدوده LocalMachine محافظت می‌شود. کد خام مدیر فنی در فایل جداگانه `technical-administrator-code.txt` تولید می‌شود. پس از تکمیل ویزارد، اعتبار کد در وضعیت bootstrap باطل می‌شود؛ اما نسخه خام فایل در نسخه فعلی برنامه به‌صورت خودکار حذف نمی‌شود و باید پس از پایان راه‌اندازی توسط مدیر Windows به‌صورت امن حذف شود.

پس از ایجاد Application Pool با نام نمونه `FleetManagement`، مجوزهای پوشه را از PowerShell با دسترسی Administrator محدود کنید. نام Application Pool را با نام واقعی جایگزین کنید:

```powershell
$path = "$env:ProgramData\FleetManagement"
New-Item -ItemType Directory -Force -Path $path | Out-Null
icacls $path /inheritance:r
icacls $path /grant "SYSTEM:(OI)(CI)F" "BUILTIN\Administrators:(OI)(CI)F" "IIS APPPOOL\FleetManagement:(OI)(CI)M"
```

Application Pool برای اجرای برنامه به دسترسی پوشه bootstrap نیاز دارد. فایل کد خام مدیر فنی را بلافاصله پس از تولید، با دستورهای زیر فقط برای SYSTEM و مدیران Windows قابل خواندن کنید. کاربران عادی و هویت Application Pool نباید مجوز خواندن این فایل را داشته باشند:

```powershell
$codeFile = Join-Path $path "technical-administrator-code.txt"
icacls $codeFile /inheritance:r
icacls $codeFile /grant:r "SYSTEM:F" "BUILTIN\Administrators:F"
```

پس از تکمیل ویزارد، فایل را با دسترسی مدیر Windows حذف کنید:

```powershell
Remove-Item -LiteralPath $codeFile -Force
```

این حذف دستی در نسخه فعلی لازم است؛ صرف باطل‌شدن هش کد در bootstrap به معنی حذف فایل خام نیست.


## بازبینی نشست‌های فعال پس از بازیابی AD

نشست‌های ورود دامنه هر پنج دقیقه از نظر فعال‌بودن حساب و عضویت در گروه‌های مجاز بازبینی می‌شوند. در صورت قطع ارتباط با AD، نشست فعلی تا انقضای عادی خودش ادامه می‌یابد و بازبینی مجدد هر یک دقیقه تلاش می‌شود. پس از بازیابی AD، اطلاعات پروفایل و نقش‌ها دوباره همگام می‌شوند؛ اگر حساب غیرفعال، قفل یا منقضی شده باشد یا دیگر عضو هیچ گروه مجازی نباشد، نشست خاتمه می‌یابد. مدیر محلی اضطراری از این بازبینی مستقل است.
