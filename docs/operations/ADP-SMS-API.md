# راهنمای API پیامک ADP

این خلاصه بر پایهٔ «راهنمای ارائه خدمات پیامک آتیه داده‌پرداز از طریق Web Service»، نسخهٔ ۱٫۲ (تیر ۱۴۰۳) تهیه شده است. خود قرارداد WSDL مرجع نهایی نام عملیات، نوع داده و شکل پیام SOAP است.

## آدرس قرارداد

`https://www.payamsms.com/services/v2/service.wsdl`

راهنما سرویس را Web Service مبتنی بر HTTP معرفی می‌کند و استفاده از WSDL را برای تولید/فراخوانی کلاینت لازم می‌داند. پیش از ارسال اعتبارنامه باید نشانی عملیاتی HTTPS و تنظیم گواهی TLS از ارائه‌دهنده تأیید شود؛ ارسال نام کاربری و رمز روی HTTP امن نیست.

## عملیات مستندشده

| عملیات | ورودی اصلی | خروجی/کاربرد |
| --- | --- | --- |
| `Send(organization, username, password, srcNumber, body, destNo[])` | سازمان، اعتبارنامه، شماره فرستنده، متن، فهرست گیرندگان | برای هر پیام شناسهٔ سرور و شمارهٔ متناظر؛ این متد حداکثر ۲۵۰ گیرنده در هر فراخوانی می‌پذیرد. |
| `SendMultiple(..., checkingMessageIds[])` | آرایهٔ فرستنده‌ها، متن‌ها، گیرندگان و شناسه‌های یکتای ساخته‌شده توسط مشتری | ارسال چندبه‌چند؛ شناسهٔ مشتری برای استعلام بعدی استفاده می‌شود. |
| `getStatuses(organization, username, password, checkingIds[])` | شناسه‌های مشتری | وضعیت پیام‌ها را به‌صورت `ID`, `checkID`, `status` برمی‌گرداند. |
| `getStatuses_OriginalID(organization, username, password, ids[])` | شناسه‌های تخصیص‌یافته توسط سرور | استعلام وضعیت بر اساس شناسهٔ اصلی پیام. |
| `Balance(organization, username, password)` | اعتبارنامه | رشتهٔ عددی موجودی ریالی. |
| `ViewReceive(organization, username, password, number, id)` | شمارهٔ اختصاصی و شناسهٔ پیام | دریافت حداکثر ۹۰ پیام ورودی؛ راهنما می‌گوید درخواست با شناسهٔ خالی پیام‌های جدید را خوانده و علامت‌گذاری می‌کند. |

در `Send` شمارهٔ گیرنده باید عددی، دارای پیش‌شمارهٔ کشور و حداکثر ۱۲ رقم باشد. تشخیص فارسی/لاتین خودکار است. شناسهٔ دریافتی `Send` برای `getStatuses_OriginalID` به کار می‌رود. در پاسخِ خطا، راهنما می‌گوید `ID` ممکن است متن/کد خطا باشد؛ بنابراین کد کلاینت باید شناسه را با دقت اعتبارسنجی کند و خطا را با وضعیت موفق اشتباه نگیرد.

## کدهای خطای ذکرشده

| کد | شرح راهنما |
| --- | --- |
| E1 | اعتبارنامه ارسال نشده |
| E2 | پارامتر لازم ارسال نشده |
| E4 / E5 | دسترسی غیرمجاز / احراز هویت ناموفق |
| E6 | اعتبار کافی نیست |
| E7 | پیام ورودی جدیدی نیست |
| E8 / E305 / E65 | شناسه نامعتبر، یافت‌نشدن پیام یا شناسهٔ لازم |
| E43 / E303 | گیرنده نامعتبر یا هیچ گیرندهٔ معتبری وجود ندارد |
| E66 / E223 | شماره فرستنده لازم یا نامعتبر است |
| E107 | بیش از ۲۵۰ گیرنده |
| E211 / E766 | متن بیش از حد مجاز یا خالی |
| E132 / E800 | متن حساس یا گیرنده در فهرست سیاه |
| E998 / E999 | بسته یا شماره منقضی شده |

راهنما برای بعضی خطاها قالب‌بندی مبهمی دارد؛ نگاشت خطا به «دائمی» یا «قابل تلاش مجدد» باید با WSDL و نمونهٔ پاسخ معتبر ارائه‌دهنده تأیید شود. خطاهای اعتبارنامه، شماره، متن و محدودیت گیرنده را نباید بدون اصلاح ورودی به شکل نامحدود دوباره ارسال کرد.

## وضعیت این پروژه

در شاخهٔ `develop` صف پایدار، ساخت پیام از رویداد مأموریت، قالب‌ها، گزارش و تلاش مجدد دستی وجود دارد. تنظیم اعتبارنامه در ویزارد آغازین فقط پس از تأیید مدیر فنی نمایش داده می‌شود. با این حال، کلاینت SOAP، پردازشگر ارسال پس‌زمینه و استعلام تحویل هنوز پیاده‌سازی نشده‌اند.

برای پیاده‌سازی قابل‌تأیید، فایل XML خود WSDL (نه فقط راهنمای PDF) و نشانی عملیاتی امن HTTPS لازم است. نسخهٔ راهنما به HTTP اشاره می‌کند و ارسال رمز ADP بدون TLS قابل‌قبول نیست. پس از دریافت قرارداد، باید فراخوانی‌ها با پاسخ‌های ساختگی در تست بررسی شوند؛ ارسال واقعی و تأیید تحویل در محیط عملیاتی بر عهدهٔ آزمون نهایی ارائه‌دهنده و مالک سامانه است.
