# تنظیمات اتصال اولیه و بازیابی

## مسئله معماری

تنظیمات عملیاتی سامانه طبق تصمیم پروژه در SQL Server نگهداری می‌شوند. با این حال، برنامه برای اتصال به SQL Server باید پیش از خواندن تنظیمات از پایگاه داده، حداقل اطلاعات اتصال را در اختیار داشته باشد.

بنابراین نگهداری «تمام» اطلاعات اتصال صرفاً داخل همان پایگاه داده از نظر فنی یک وابستگی دوری ایجاد می‌کند: برای خواندن نشانی و رمز SQL باید ابتدا به SQL متصل شده باشیم.

## راهکار لازم

- فقط حداقل اطلاعات Bootstrap اتصال SQL در محل محافظت‌شده سرور نگهداری شود.
- سایر تنظیمات عملیاتی پس از برقراری اتصال در SQL ذخیره شوند.
- مسیر اضطراری Administrator فقط برای اصلاح اتصال و بازیابی باشد.
- فایل Bootstrap نباید در Git یا نسخه عمومی مخزن ثبت شود.
- پس از پیکربندی، ACL فایل فقط به هویت App Pool و مدیر فنی مجاز شود.

## نکته امنیتی

ذخیره تنظیمات حساس بدون رمزنگاری در SQL یک ریسک پذیرفته‌شده در تصمیم فعلی پروژه است، اما حفاظت از خود SQL Server، حساب کاربری برنامه و فایل پشتیبان همچنان ضروری است.
