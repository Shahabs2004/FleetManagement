# امنیت و استقرار

## محیط اجرا

- برنامه روی Windows Server و IIS اجرا می‌شود.
- SQL Server موجود سازمان استفاده می‌شود.
- نسخه نخست روی یک سرور IIS مستقر می‌شود.
- دسترسی کاربران از شبکه داخلی سازمان است.
- مرورگرهای هدف: نسخه پایدار Microsoft Edge، Google Chrome و Mozilla Firefox.

## راه‌اندازی اولیه

- اولین اجرای سایت وضعیت راه‌اندازی را تشخیص می‌دهد و کد یک‌بارمصرف ایجاد می‌کند.
- کد خام فقط در فایل محلی محدودشده سرور قرار می‌گیرد و در گزارش برنامه ثبت نمی‌شود.
- پس از ایجاد حساب مدیر محلی، فایل کد اولیه حذف و هش آن باطل می‌شود.
- حساب محلی Administrator مستقل از Active Directory برای راه‌اندازی و دسترسی اضطراری در نظر گرفته می‌شود.
- SQL Server و پایگاه داده در ویزارد تنظیم می‌شوند و Migrationها ساختار جداول را ایجاد می‌کنند.
- راه‌اندازی می‌تواند با AD ناقص تکمیل شود؛ کاربران عادی تا برقراری AD قادر به ورود نیستند.
- اختلال پیامک مانع فعال شدن سامانه نمی‌شود.
- در پایان، آزمون آمادگی بهره‌برداری اجرا می‌شود.

## حفاظت از فایل‌های bootstrap

- فایل bootstrap با DPAPI در محدوده LocalMachine رمزنگاری می‌شود.
- فایل شامل حداقل اطلاعات اتصال SQL و هش رمز مدیر محلی است.
- رمز مدیر محلی با PBKDF2 و نمک تصادفی هش می‌شود؛ رمز خام ذخیره نمی‌شود.
- فایل کد یک‌بارمصرف در پوشه‌ای خارج از ریشه وب قرار می‌گیرد و پس از مصرف حذف می‌شود.
- پوشه داده باید فقط برای SYSTEM، گروه Administrators و هویت Application Pool برنامه مجوز داشته باشد.
- فایل bootstrap و کد راه‌اندازی نباید در Git، گزارش‌های عمومی یا پوشه قابل دانلود وب قرار گیرند.
- DPAPI LocalMachine به‌تنهایی مجوزهای NTFS را جایگزین نمی‌کند؛ ACL پوشه باید در زمان استقرار اعمال شود.
- در صورت انتقال برنامه به سرور جدید، فایل bootstrap باید با فرایند بازیابی کنترل‌شده و مجوزهای مناسب منتقل یا دوباره تولید شود.

## بازیابی اضطراری

- در قطع SQL، فقط مسیر اضطراری محدود برای حساب Administrator در دسترس است.
- این مسیر برای اصلاح تنظیمات اتصال SQL و آزمون مجدد اتصال است.
- داده‌های عملیاتی در زمان قطع SQL در دسترس نیستند.
- حداقل داده لازم برای احراز هویت اضطراری و اتصال مجدد خارج از پایگاه داده و در محیط محافظت‌شده سرور نگهداری می‌شود.

## تنظیمات و اسرار

تصمیم ثبت‌شده پروژه این است که تنظیمات در SQL نگهداری شوند و رمزنگاری تنظیمات در محدوده اولیه درخواست نشده است. این تصمیم ریسک افشای اطلاعات در صورت دسترسی غیرمجاز به پایگاه داده را افزایش می‌دهد.

**هشدار:** این مخزن عمومی است. هیچ مقدار واقعی یا نمونه قابل استفاده‌ای از رمز SQL، اطلاعات حساب سرویس AD، رمز ADP، کلیدها، شماره‌های محرمانه، داده شخصی یا فایل پشتیبان نباید در مخزن قرار گیرد.

در محیط عملیاتی باید دسترسی شبکه و حساب‌های SQL و Windows محدود شوند. حتی اگر رمزنگاری داده‌های تنظیمات در محدوده فعلی انتخاب نشده باشد، حفاظت از دسترسی به SQL Server و نسخه‌های پشتیبان ضروری است.

## حساب SQL

طبق تصمیم فعلی، یک حساب SQL برای ساخت/به‌روزرسانی ساختار و اجرای روزمره برنامه استفاده می‌شود. این حساب نباید sysadmin باشد؛ سطح دسترسی دقیق آن باید متناسب با Migration و عملیات برنامه تعیین شود.

## به‌روزرسانی

- انتشار نسخه جدید روی IIS کنترل‌شده است.
- سازگاری نسخه و Migrationها بررسی می‌شود.
- پیش از Migration باید وجود نسخه پشتیبان معتبر بررسی شود.
- در شکست Migration از اجرای نسخه ناسازگار جلوگیری می‌شود.
- بازگشت برنامه و پایگاه داده باید به‌عنوان دو عملیات مرتبط و جداگانه طراحی شود.

## پیامک

- سرویس ADP وابستگی غیرمسدودکننده است.
- خطای پیامک نباید گردش‌کار مأموریت را متوقف کند.
- اطلاعات حساس سرویس پیامک نباید در گزارش‌ها یا مخزن عمومی افشا شوند.
